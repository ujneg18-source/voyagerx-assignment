01이 순서로 함께 진행하겠습니다

  1. 대상과 목표, 기한을 확인합니다

    누가 쓸 것인지, 어떤 불편을 해결할지, 언제까지 필요한지 먼저 확인합니다. 꼭 포함할 기능과 이번에는 만들지 않을 범위를 정리합니다.

    결과물 · 대상·목표·기한·작업 범위를 정리한 문서

  2. 글이나 화면 초안으로 방향을 확인합니다

    안내문은 문장 초안으로, 서비스는 간단한 화면으로 보여 드립니다. 버튼을 어디에 둘지, 어떤 내용을 보여 줄지 함께 확인한 뒤 세부 내용을 다듬습니다.

    결과물 · 검토할 수 있는 글·화면·기능 목록

  3. 진행 상황과 결정할 일을 공유합니다

    완료한 일, 다음 할 일, 함께 결정할 일을 구분합니다. 일정에 영향을 주는 변경은 이유와 선택지를 함께 전달합니다.

    결과물 · 진행 현황과 결정이 필요한 항목

  4. 사용자가 하려던 일을 끝낼 수 있는지 확인합니다

    처음부터 끝까지 직접 사용하며 빠진 단계와 오류를 찾습니다. 사용자 반응이나 기록이 있다면 어느 단계에서 멈추는지, 완료까지 얼마나 걸리는지도 확인해 다음 개선점을 정리합니다.

    결과물 · 확인한 문제·근거·다음 작업 목록

02도란도란에서 화면을 보며 개발 범위를 정했습니다

위 2단계 ‘초안 공유’를 실제 프로젝트에서 적용한 사례입니다.

웹 화면 초안을 직접 만들어, 팀원들과 먼저 구현할 기능을 정했습니다. ‘도란도란’은 아이의 읽기 수준에 맞춰 전래동화를 만드는 AI 서비스입니다. 저는 3인 팀의 팀장으로 기획과 데이터 준비를 맡았습니다.

만든 것
개발 초기에 서비스의 웹 화면과 디자인 초안을 직접 만들었습니다. 기능을 설명할 때 팀원들이 함께 볼 수 있는 자료로 사용했습니다.
함께 정한 것
같은 화면을 보면서 서비스에 꼭 필요한 기능과 우선 구현할 범위를 맞췄습니다. 이후 기획·데이터는 제가, 서버 기능과 사용자 화면은 각 담당 팀원이 맡아 개발했습니다.
연결한 기준
아이의 읽기 수준을 20단계로 나누고, 단계마다 사용할 낱말과 문장 길이를 정리했습니다. 이 기준이 AI의 동화 생성과 사용자 화면에 함께 반영되도록 팀과 조율했습니다.

01일을 요청할 때

POST/work-requests업무 요청

원하는 결과를 알려 주세요. 아직 정리 중인 요청도 함께 구체화하겠습니다.

아래 예시의 상황 처음 사용하는 고객이 검색 시작일·종료일 선택을 어려워해, 날짜 선택 안내문을 고치는 업무입니다.

이런 정보가 있으면 좋습니다

goal목표
무엇을 해결하거나 바꾸고 싶은가요?
context상황
누가, 어느 화면이나 과정에서 겪는 문제인가요?
due기한
언제, 어떤 수준의 결과가 필요한가요?
reference참고 자료
관련 화면·문서·사용자 의견을 함께 보면 더 빨리 맞출 수 있습니다.

이렇게 요청하고, 이렇게 확인합니다

요청 예시application/json
{
  "goal": "날짜 선택 안내를 쉽게",
  "context": "처음 사용하는 고객",
  "due": "금요일까지 초안",
  "reference": "현재 안내 화면"
}
답변 예시200 OK
이해한 내용
처음 쓰는 고객이 날짜 선택을 마칠 수 있도록 안내를 다듬는 일이군요.
먼저 보여 드릴 것
버튼 이름과 선택 순서가 보이는 안내 초안을 만들겠습니다.
함께 확인할 것
고객이 자주 멈추는 화면도 알려 주시면 초안에 반영하겠습니다.

먼저 · 참여자를 모집해 시제품 확인

  • 별도 모집이 필요합니다. 뉴스 검색 경험이 있는 참여자에게 지금 만든 날짜 선택 화면을 써보게 합니다.
  • “1991년 11월 기사를 찾아보세요”처럼 날짜를 제시합니다. 최근 날짜와 오래된 날짜를 모두 시도하게 합니다.
  • 달력형 선택기는 월·일까지 고르지 않아도 연도만으로 검색할 수 있게 만들었습니다. 이 기능의 의도를 이해하는지 확인하려고, 종료 연도로 2026년을 고른 뒤 “종료일이 언제인가요?”라고 묻습니다. 2026.01.01로 이해했는지 살펴봅니다.
  • 사람마다 세 방식을 써보는 순서를 바꾸고, 날짜를 잘못 고르거나 도움을 요청하는 부분을 기록합니다.

그다음 · 실제 방문자 대상 A/B 테스트

  • 이 단계는 별도 참여자 모집 없이 실제 서비스 방문자 중 실험 대상에게 진행합니다. 서비스 운영팀이 기능과 측정 환경을 구현해야 합니다.
  • A/B/n은 현행과 여러 개선안을 비교하는 무작위 실험입니다. A–B, A–C를 각각 비교합니다.
  • 첫 노출 전에 배정하고 재방문에도 같은 안을 제공합니다. 실험 기간·최근 기간 버튼·검색 결과 등 나머지 조건은 동일하게 둡니다.
  • 검증할 가설: 긴 스크롤을 줄이면 기간 설정 완료율이 높아질 것입니다. 오래된 날짜에서의 차이는 동일한 사용성 과제로 확인합니다.

두 단계 모두 실행 전 계획입니다. 실서비스 A/B 테스트는 운영팀과의 구현·측정 협업을 전제로 합니다.

시간·중단율
시간은 완료한 첫 시도의 중앙값으로 비교하고, 중단율을 함께 봅니다. 적용 후 자동으로 창이 닫힌 경우는 중단에서 제외합니다. 검색 실패는 별도 품질 지표로 확인합니다.
정확성·편의성
별도로 모집한 참여자가 시제품을 써볼 때, 요청한 기간과 실제 선택이 일치하는지 확인합니다. 성공·실패 모두 종료 직후 쉬움 점수(1점 매우 어려움~7점 매우 쉬움)와 이유를 묻습니다. 형식 오류는 원인 분석에 쓰고, 달력과 입력 방식의 정확성은 같은 과제로 비교합니다.

완료한 날짜만으로 실험 사용자를 나누면 중단한 사람이 빠집니다. 최근·오래된 날짜 비교는 사용성 과제로, PC·모바일 비교는 사전에 정한 실험 분석으로 확인합니다.

현행과 비교
A–B, A–C의 복수 비교를 반영한 신뢰구간으로 차이의 불확실성을 확인합니다. 통계적으로 구분되고 사전 최소 개선폭도 충족하는 안을 후보로 삼습니다. 두 안이 모두 통과하면 B–C를 추가 검증합니다.
품질·확대 기준
검색 실패·응답 지연은 사전 허용 범위와 비교하고, 사용성 테스트에서 발견한 심각한 날짜 오선택은 먼저 해결합니다. 표본이 작거나 ‘유의한 악화가 없다’는 이유만으로 안전하다고 판단하지 않습니다.
보류·재검증
계획한 표본과 기간을 채우기 전에 좋은 결과만 보고 종료하지 않습니다. 기기별 차이는 충분한 표본으로 추가 확인하며, 판단이 불확실하면 현행 유지 또는 재실험을 선택합니다.

‘효과음’도 글을 읽는 목소리입니다

이 표의 효과음은 AI 목소리 탭의 기능입니다. “짝짝” 같은 녹음된 소리를 고르는 것이 아니라, 직접 쓴 짧은 말을 AI 목소리로 넣습니다.

좀 더 자세히 설명해 주세요

각 기능의 메뉴에서 새로 넣기, 내용·목소리 수정, 적용 범위 선택을 할 수 있습니다.

클립 삽입
새 클립으로 삽입 · 입력한 문장을 읽는 새 클립과 자막을 추가합니다.
텍스트 수정 · AI 목소리 클립이 읽을 문장을 고칩니다.
목소리 수정 · AI 목소리 클립의 목소리와 설정을 바꿉니다.
효과음
원하는 위치에 “띠용!”, “잠깐!” 같은 표현을 입력하면 원래 음성과 자막을 유지하면서 목소리를 덧붙입니다.
짧은 반응이나 강조에 활용하고, 원래 말과 겹치지 않도록 위치와 음량을 확인해 주세요.
자막 더빙
전체 클립에 더빙하기 · 프로젝트 전체를 대상으로 더빙합니다.
현재 씬의 모든 클립에 더빙하기 · 지금 보고 있는 씬에 속한 클립들을 더빙합니다.
현재 / 선택된 클립에 더빙하기 · 체크하지 않으면 현재 클립, 체크하면 선택한 클립들을 더빙합니다.
더빙 목소리 전체 수정 · 이미 만든 자막 더빙의 목소리를 한꺼번에 바꿉니다.
더빙 전체 삭제 · 자막 더빙만 지웁니다. 영상·자막·별도로 넣은 효과음은 유지됩니다.

더빙할 범위를 고른 뒤 목소리를 선택하고 ‘목소리 사용’을 누릅니다. 범위 안에 이미 더빙된 클립이 있으면 그대로 두고, 더빙이 없는 클립에 추가합니다.

더빙 삭제는 실행 취소와 다릅니다. 삭제 후에도 바뀐 클립 길이와 원래 음성의 음소거 상태가 남을 수 있으니 확인해 주세요.

문의 1 · 자동 씬 나누기

사용자 문의
Q. 자동 씬 나누기는 어떤 기능인가요? 언제 쓰는지 궁금해요.
Vrew 답변

안녕하세요, Vrew입니다.
자동 씬 나누기 기능에 관심 가져주셔서 감사합니다.

어떤 기능인가요?

영상 속 말의 흐름을 분석해, 내용이 이어지는 클립끼리 하나의 ‘씬’으로 묶어 주는 기능입니다. 클립은 영상 조각이고, 씬은 비슷한 내용을 담은 클립을 모은 묶음입니다.

씬마다 내용에 맞는 제목도 자동으로 붙어서, 긴 영상도 주제별로 한눈에 훑어보실 수 있습니다. 아래의 17초 자기소개 영상에서는 인사와 자기소개 부분이 두 개의 씬으로 나뉘었습니다.

언제 쓰면 좋나요?

  • 강의·인터뷰·브이로그처럼 주제가 여러 번 바뀌는 긴 영상을 편집할 때
  • 특정 부분을 찾아 고치거나 씬 단위로 순서를 바꾸고 싶을 때
  • 영상 목차를 만들거나 하이라이트를 고를 때

사용 방법

빨간 네모가 눌러야 할 곳입니다. 사진을 누르면 전체 화면을 볼 수 있어요.

  1. 상단 편집 탭에서 자동 씬 나누기를 눌러 주세요.
  2. 나눌 씬을 체크한 뒤 나누기를 눌러 주세요.

    영상 전체를 나누려면 전체 선택을 누르시면 됩니다.

  3. 나뉜 씬과 제목을 확인해 주세요.

    예시에서는 ‘영상 편집기 소개 및 인사’와 ‘자기소개’로 나뉘었습니다.

예시 영상에서는 이렇게 달라졌어요

실행 전
씬 1개
→
실행 후
씬 2개

영상 길이는 17초, 클립 수는 6개로 유지됐습니다. 이 숫자는 예시 영상의 결과이며, 씬 수와 제목은 영상 내용에 따라 달라집니다.

원하는 대로 나뉘지 않았다면

실행 취소로 되돌리거나 씬을 직접 합치고 나눠 조정하실 수 있습니다. 자동으로 붙은 제목도 영상 내용에 맞는지 확인해 주세요.

더 궁금하신 점이 있으면 언제든 편하게 문의해 주세요.
감사합니다.

문의 2 · 머뭇거린 부분 지우기

사용자 문의
Q. 말하다 멈추거나 “안녕 안녕하세요”처럼 반복한 부분을 지우고 싶어요.
Vrew 답변

안녕하세요, Vrew입니다.
말 사이에 멈춘 구간이나 반복한 말을 정리하고 싶으시군요.

소리 없이 멈춘 구간은 ‘무음 구간 줄이기’로 줄이고, 소리 내어 반복한 말은 ‘컷편집 줄’에서 지우시면 됩니다. 상황에 맞는 방법을 아래에서 안내해 드릴게요.

소리 없이 멈춘 구간을 줄이려면

강의나 인터뷰에서 말 사이의 긴 공백을 한 번에 정리하고 싶을 때 사용해 보세요.

  1. 편집 → 무음 구간 줄이기를 눌러 주세요.
  2. 찾을 무음의 길이와 남겨 둘 길이를 정해 주세요.

    예를 들어 ‘1초 이상’을 찾고 ‘0초’를 남기면, 1초 이상 조용했던 구간을 찾아 남기지 않고 줄입니다. 숨 쉴 틈을 두고 싶다면 남길 길이를 늘려 주세요.

  3. 적용할 범위를 고르고 실행한 뒤 재생해 주세요.

    말이 너무 급하게 이어진다면 되돌린 뒤 남길 길이를 늘려 다시 조정해 주세요.

예시 영상 · 적용 전
17초
→
적용 후
13초

1초 이상 무음을 찾아 0초만 남긴 예시입니다. 실제로 줄어드는 시간은 영상과 설정에 따라 달라집니다.

“안녕 안녕하세요”처럼 반복한 말을 지우려면

반복한 말은 소리가 있으므로 무음 줄이기로 지워지지 않습니다. 자막 위에 단어별로 표시된 컷편집 줄에서 지워 주세요. 아래 빨간 네모는 첫 번째 ‘안녕’을 표시한 것입니다.

  1. 컷편집 줄에서 지울 단어 앞에 커서를 놓아 주세요.

    아래쪽 자막 문장만 고치면 자막만 달라질 수 있으니, 위쪽의 실제 발화 내용을 선택해 주세요.

  2. 앞으로 지우기를 눌러 주세요.

    Mac에서는 fn + Delete를 누릅니다. 한 번 지운 뒤 재생해 필요한 말까지 지워지지 않았는지 확인해 주세요.

예시 클립 · 편집 전
1.62초
→
편집 후
0.92초
지우는 방향을 확인해 주세요

클립 맨 앞에서 뒤로 지우기를 누르면 이전 클립과 합쳐질 수 있습니다. 예시처럼 첫 단어를 지울 때는 앞으로 지우기를 사용해 주세요. 잘못 편집했다면 실행 취소로 되돌릴 수 있습니다.

마지막으로 해당 구간을 재생해 말이 자연스럽게 이어지는지 확인해 주세요.
더 궁금하신 점이 있으면 언제든 편하게 문의해 주세요. 감사합니다.
